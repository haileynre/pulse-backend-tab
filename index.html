Pulse Backend tab

Spec for Matt’s Cursor. Build this in the New Reach HQ app. Nov 4, 2026.

Add a Backend tab on NR Pulse webinar events. The tab tracks setup checkboxes in the existing History log. Test Lead Intake looks up a registrant the same way a live Nov 4 check did, then writes that diagnosis into Notes.

The app is finance.newreach.com/nr-pulse. It is a Next.js page at app/(dashboard)/nr-pulse, backed by a tRPC router named nrPulse. This spec does not live in that repo.

How the team sets up and tests a webinar

The Backend tab follows this sequence. A Pulse calendar item is the trigger. The same steps apply to Guest Host Live Webinar. The only difference is which Zoom account hosts the webinar.

Webinar setup

  1. Pulse calendar item. This is the trigger.
  2. Create the Zoom webinar in the support@subto.com account.
  3. Create the ActiveCampaign tag.
  4. Create the ActiveCampaign form. Manual for now.
  5. Set up SMS reminders.
  6. Embed the new ActiveCampaign form on the landing page. Manual for now.

Webinar testing

Someone fills out the form on the landing page. That step is manual for now. Test Lead Intake then checks the rest, and Notes records each result.

  1. Close: the lead has an 01. New Activity. The Funnel? field must read Live Webinar - MM/DD/YYYY. That date must match the date on the landing page and the date of the webinar in Pulse.
  2. ActiveCampaign: the date on the tag must match the landing-page date, the Pulse webinar date, and the date in Funnel?.
  3. Zoom: the test lead is registered on the webinar. Zoom Join URL is that registrant’s personal join link, the one Zoom issues for that email. It is not the shared webinar link on the Pulse card.
  4. SMS: the lead is on the SMS reminders list. That list is the SMS Verified tab of the webinar’s sheet.

Guest Host Live Webinar

Same setup and the same tests. The Zoom host changes by brand:

  • Subto guest: pace@subto.com
  • Gator guest: support@gatormethod.com

A Live Webinar, Replay Webinar, or Ask Me Anything still uses support@subto.com unless the card says otherwise. When the test looks up the registrant, it uses the host on the Pulse item, and Notes names that account.

Where the tab goes

The event dialog already has Details, Integrations, Zoom settings (only for a Zoom event type), SMS copy (only when confirmSms or reminders is on), RSVP, and History. Add Backend as the last tab. Do not rename or remove the tabs above it. Leave the existing “n8n pending” line and the sentence “Changes are recorded in the History tab.”

Show the tab when either is true:

  • mechanismCode is live (LIVE Webinar), likelike (Replay Webinar), or ama (Ask Me Anything).
  • The mechanism label, compared case-insensitively after trimming, is pace live webinar or guest host live webinar.

Those last two mechanisms are not in nrPulse.mechanisms today. Do not create them. The label check is what makes the tab appear after someone adds them. When their codes exist, add the codes too, so a later rename does not hide the tab.

Current mechanisms: live, likelike, challenge, ama, inperson, internal, conversion_sprint. Hide the tab for the four not listed above.

What the tab looks like

Match the open event dialog. The rough mock is layout only.

Platform Setup

Nine rows. Each row is a checkbox, the label, and on the right the completion stamp. The stamp is empty while unchecked. When checked, format the timestamp with the same formatter the History tab already uses for changedAt, then the actor: the logged-in user’s email, or n8n when no user checked it. Example: Oct 8, 2026, 9:56 AM · n8n.

Checking and unchecking both save immediately. They do not wait for the dialog Save button, and Discard does not undo them. A person can uncheck a box n8n checked.

Platform Check

A field labeled Submit Test Lead Email, and a button labeled Test Lead Intake. Disable the button until the value is an email. The button does not register anyone and does not write to Close, ActiveCampaign, Zoom, the registry, or the sheet.

  • Close Account, full width, with a link affordance when the value is a URL.
  • Close Custom Activity “Funnel?” Field, and Lead Owner.
  • Initial Lead Type, and Last Lead Type.
  • Initial Lead Source, and Last Lead Source.
  • Active Campaign Account, full width, link affordance when it is a URL.
  • Webinar Tag (Main), and Webinar Tag (Email).
  • Member Communications: Zoom Join URL, and SMS Reminders. Zoom Join URL is the personal join link Zoom gave this registrant. SMS Reminders is the reminder body only when this phone is on the SMS Verified tab. Otherwise it stays empty and Notes explains the sheet.
  • Notes, full width. This is the diagnosis. The required wording is in Notes.

These inputs stay editable after a lookup so someone can correct a value. Hand edits use the dialog’s existing dirty/save path. Each hand-edited field writes one History row the same way other event fields already do.

History

The History tab already lists nrPulse.changes: summary, then changedByEmail (or changedByLegacy) when present, then changedAt. n8n rows have a null email and summaries such as “Zoom link added by n8n”. Reuse that table. Do not build a second log.

Write one row per checkbox toggle:

  • field: backend.zoom_webinar (and the other keys)
  • oldValue / newValue: unchecked or checked
  • summary: “Created Zoom Webinar checked” or “Created Zoom Webinar unchecked”. For an n8n check, put “by n8n” in the summary, because a null email is omitted by the History UI.
  • changedByEmail: the session user from nrPulse.me, or null for n8n

Write one row for each Test Lead Intake run, not one row per filled field. field is backend.testLead. summary is “Test lead intake for <email>”. newValue is the Notes text. changedByEmail is the session user. Unchecking does not delete older rows.

Checklist storage

New table, one row per event plus item key: checked, completedAt, completedByEmail (null for n8n), source (user or n8n). Store the last Platform Check snapshot on the event: the email, every field above, and Notes.

Seed once, the first time the tab loads, and do not write a new History row when the original n8n History row already exists.

  • Created Zoom Webinar: checked when zoomWebinarId is set. Stamp time comes from the History row whose summary is “Zoom link added by n8n”. If that row is missing, use the event time the link was stored and write one History row.
  • Active Campaign Tag(s): checked only when acTag is non-empty. A blank acTag stays unchecked.
  • Do not auto-check the other seven from a filled landing page, SMS copy, or any other field a person typed.

The existing n8n callback that already writes zoomWebinarId, zoomLink, registrationLink, and acTag onto the card should call the same mark function. Mark zoom_webinar when the callback sets a webinar id. Mark ac_tags when it sets acTag. No change to workflow 322e (RldCoGPgDE3VUEGJ) or 322s (SYo2K0IASwWVSAdH) is required for those two boxes.

Last write wins. A newer n8n completion may re-check a box a person had unchecked. Replaying the same completion (a completedAt that is not newer) must not re-check it. Later setup steps check their box only by calling this mark function with source: "n8n". Do not invent those signals. 322t (AC form clone) is a draft and is not a source.

Test Lead Intake

Authenticated tRPC mutation. The browser never calls n8n, Close, ActiveCampaign, Zoom, or Google Sheets directly. If the Pulse server already has those clients, call them there. If martech.scheduled_events, martech.webinar_registrants, and public.webinar_actions_for are only reachable from n8n, add one read-only n8n workflow and call it server-side with a shared secret. Leave that workflow inactive until this mutation is ready to call it. Do not pause any Zap, do not set cutover, and do not activate unrelated workflows.

This lookup was proven on Nov 4, 2026 against Creative Finance Training with Pace Morby (Zoom webinar 85977280124, 3:00 PM Arizona) for hailey@newreach.com. Build the mutation so it walks the same objects. Do not invent a second recipient list.

Notes

Notes is the diagnosis, not a one-line miss list. Every run replaces the system portion of Notes with plain sentences a teammate can read without opening n8n. Keep any text the person typed under a Team notes: heading. No stack traces. A thrown error is one sentence: Close: error — <short message>. The other lookups still run.

Write these blocks, in this order, and skip a block only when that system was not queried:

  1. One line: Test lead intake · <timestamp in the event timezone> · <session email>.
  2. The sheet URL from scheduled_events.spreadsheet_url, and whether the email is on All Registrants and whether the email and the contact phone are on SMS Verified. Say the phone in E.164.
  3. The reminder switch and the confirmation switch: on, or blocked, and blocked_by (global or webinar). If both are off, say the hub is not writing a sheet row while they are off.
  4. ActiveCampaign: whether the main tag is on the contact, the contact id, the association time (not the tag’s own created time), and whether that time is this registration or an older one. Whether the (Email) twin is on the contact. If the join-link field points at a different webinar id, name that id and when it was written.
  5. Close: the lead URL, the 01. New Activity time, Funnel?, Lead Type, and the owner name. If that activity was created for a different email on the same lead, say so and name the other email. Mention a second same-day activity when its Funnel? date is a different webinar.
  6. Zoom: whether a registrant row or sheet join_url exists for this webinar id. If the check did not scan every Zoom registrant, say that Zoom’s list does not filter by email and give the registrant count, instead of claiming the person is absent from Zoom.

Registry and the sheet

Look up martech.scheduled_events by webinar_id equal to this event’s zoomWebinarId. If that misses, look up martech.pulse_event_map by pulse_event_id and then the registry row. Read spreadsheet_url, ac_tag, sms_confirm, and the reminder slot 324a uses (sms1 by default). Put the reminder body in SMS Reminders only when this email’s phone is on SMS Verified. If the body exists but the phone is not on that tab, leave SMS Reminders blank and put the body, the sheet URL, and the miss in Notes.

If Pulse’s own reminderSmsCopy (nrPulse.getSmsCopy) differs from the registry body, still use the registry body and say the SMS copy tab differs.

Look up the sheet by the email column and the phone column. Try the phone as stored and as E.164. Search the whole column. An empty lookup is a miss, not an error.

Zoom

Extract the mailbox from zoomAccount. The sample value is Support@subto.com - Webinars (Unlimited). The email is the part before - . Live, Replay, and Ask Me Anything webinars are created under support@subto.com. Guest Host Live Webinar uses pace@subto.com for Subto and support@gatormethod.com for Gator. Notes names the account that was searched. Zoom GET /webinars/{id}/registrants ignores an email query and returns the newest page only. Do not page thousands of registrants from Pulse.

A pass on Zoom means the test email is a registrant. A pass on Close means Funnel? is Live Webinar - MM/DD/YYYY and that date matches the Pulse webinar date and the landing-page date. A pass on ActiveCampaign means the date in the tag matches those same three dates.

Zoom Join URL is the personal link Zoom creates for that registrant. On the registrant record it is join_url, the long link with that person’s token. It is not the webinar’s shared join link, not the Pulse card’s zoomLink, and not scheduled_events.join_url.

Read it from the Zoom registrant for this email. If Zoom’s list cannot be filtered, use a stored copy of that same personal link, in this order, and only when the URL is the registrant link for this webinar id:

  1. join_url on the All Registrants or SMS Verified row for this email.
  2. join_link on martech.webinar_registrants for this webinar id plus email.
  3. The brand’s ActiveCampaign join-link field, only when the URL contains this webinar id (Subto field 41).

If the only link available is the shared webinar link, leave Zoom Join URL blank and say so in Notes. A shared link does not prove this lead was registered.

ActiveCampaign

Use the brand account map already used by the webinar form work:

  • subto → subto1304.activehosted.com
  • gator → pacemorby.activehosted.com
  • zdb (also zero down) → zerodownbusinesses.activehosted.com
  • tc / tttc / toptier → toptiertc.activehosted.com

Find the contact by the submitted email. Active Campaign Account becomes {admin}/app/contacts/{id}. Unknown brand, or no contact: leave the link and both tag fields blank and note it.

Tags come from the tags on that contact, ordered by the contact-tag association time (contactTag.cdate), not the tag’s own created date. Always write that association time into Notes. A tag applied on an earlier day is not evidence of the registration being tested.

  • A tag whose name ends with (Email), ignoring case, is an email twin. The main tag is the same name without that suffix.
  • If both are on the contact, they are a pair. Prefer the pair whose main tag equals the registry ac_tag. Otherwise use the pair with the latest association time.
  • Webinar Tag (Main) is the tag that does not contain the word email. Webinar Tag (Email) is the twin.
  • If only one side is present, fill that side and say the twin is missing.
  • If no (Email) pair exists, put the most recent tag whose name does not contain “email” in Main, and the most recent tag whose name contains “email” in Email, and say they were not a matched pair.
  • If the main tag does not equal the registry ac_tag, still show the contact’s tags, and name the registry tag that was expected.
  • Read the join-link field (Subto field 41). If its URL’s webinar id is not this event’s zoomWebinarId, do not use it as Zoom Join URL. Notes names the other id and the field’s udate.

Close

Read only. 01. New Activity is a live edge between acquisition and onboarding. Do not create a lead, a contact, or an activity when something is missing.

Pick the Close org from the Pulse brand: Subto, Gator, Zero Down, Top Tier, Deal Scout, Owners Club. An unmapped brand skips Close and is noted.

Search leads by the email. The email match includes secondary addresses. One lead: Close Account is https://app.close.com/lead/{id}. More than one lead: leave every Close field blank and list the lead names and URLs in Notes. Do not pick one.

A single lead often carries more than one email. On Nov 4, hailey@newreach.com and melissa@newreach.com were both on lead_Je9eQLQ9X1xpiErsvciIcgvni6GuQer9Lw5onk3B8En, and the 01. Filling Funnel? from the newest activity on “the lead that has this email” attributes someone else’s registration to the person being tested.

Attribute an activity to the submitted email only when one of these is true:

  • The activity’s contact email is the submitted email.
  • martech.webinar_registrants for this webinar id plus the submitted email points at that lead.
  • The hub execution that created the activity (323a nodes custom_activity and close_upsert) used the submitted email.

If the only dated activity belongs to a different email on the lead, leave Funnel? and Lead Owner blank and explain it in Notes, including the other email, the Funnel? value, the owner name, and the time. If a later activity on that lead has a different webinar date in Funnel?, mention it in the same paragraph.
